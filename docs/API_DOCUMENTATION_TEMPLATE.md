# API 文档模板

本文档提供了 NOS 内核公共 API 的文档注释模板和规范。

## 文档注释规范

所有公共 API 必须遵循 Rust 文档注释规范：
- 使用 `///` 进行文档注释（项注释）
- 使用 `//!` 进行模块级文档注释
- 使用 markdown 格式编写文档
- 提供清晰的示例代码

```rust

///

/// - 不变性条件1

## 9. 文档注释最佳实践

### 9.1 一般原则

1. **清晰简洁**: 文档应该清晰、简洁、易于理解
2. **完整**: 覆盖所有公共 API
3. **示例优先**: 提供可运行的示例代码
4. **保持更新**: 代码修改时同步更新文档

### 9.2 示例代码

- 使用 `no_run` 标记不能直接运行的示例
- 使用 `ignore` 标记仅用于说明的代码
- 确保示例可以编译（除非使用 `ignore` 或 `no_run`）
- 示例应该展示常见用法

### 9.3 文档测试

```rust
/// 示例函数
///
/// ```
/// assert_eq!(add(1, 2), 3);
/// ```
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}
```

### 9.4 性能和安全性说明

- 在文档中明确标注性能特征
- 说明安全性要求和未定义行为
- 标注可能 panic 的情况

### 9.5 模块组织

- 在模块级文档中提供概览
- 使用内部链接连接相关项
- 提供使用指南和教程

## 11. 文档检查清单

在提交代码前，检查以下内容：

- [ ] 所有公共类型、函数、方法都有文档注释
- [ ] 文档包含清晰的示例
- [ ] 示例代码可以编译运行
- [ ] 包含错误处理说明
- [ ] 包含性能考虑说明
- [ ] 包含线程安全说明
- [ ] 包含 Panics 说明（如果适用）
- [ ] 包含 Safety 说明（对于不安全代码）
- [ ] 模块级文档完整
- [ ] 文档与代码实现一致

## 13. NOS 特定规范

### 13.1 内核代码特殊考虑

- **中断安全**: 说明是否可以在中断上下文中调用
- **原子性**: 说明操作的原子性保证
- **内存分配**: 说明是否可能触发内存分配
- **锁顺序**: 说明获取锁的顺序要求

### 13.2 系统调用文档

系统调用的文档应包含：
- POSIX 标准对应关系
- 参数验证规则
- 返回值规范
- 错误码映射
- 性能特征

### 13.3 驱动程序文档

驱动程序的文档应包含：
- 硬件接口描述
- 寄存器映射
- 中断处理
- DMA 操作
- 电源管理
